# SunGET Solar Infra — website

Static website (HTML + CSS + vanilla JavaScript) for **www.sungetsolarinfra.com**, with
[Supabase](https://supabase.com) as the backend for enquiry forms, careers, the photo
gallery, solar utility products and the admin panel.

There is no server code and no build step is required to *run* the site — any static
host works (Hostinger/cPanel, Netlify, Vercel, GitHub Pages, S3…).

---

## 2. Run locally

```bash
cd sunget
python3 -m http.server 8080      # or: npx serve .
# open http://localhost:8080
```

Opening the files directly (`file://`) mostly works, but the admin "Pages" editor and
some browsers' fetch rules need a real local server. The VS Code launch configuration in
`.vscode/launch.json` expects the server on port 8080.

## 3. Configuration

All runtime configuration lives in **`src/sg-config.js`**:

| Key | What it is |
|---|---|
| `SUPABASE_URL` | Supabase project URL |
| `SUPABASE_ANON_KEY` | Supabase **publishable / anon** key (public by design) |
| `WHATSAPP_NUMBER` | Number used by the solar calculator's WhatsApp button (`91XXXXXXXXXX`) |
| `PHONE_DISPLAY` | Phone number shown in messages |

`.env.example` lists the same names. A static site cannot read `.env` files, so edit
`src/sg-config.js` directly. **Never** put the Supabase `service_role` / secret key in any
file of this website.

## 4. Supabase setup (must be checked before going live)

The publishable key is visible to every visitor. It is only safe if **Row Level Security
(RLS)** is enabled with the right policies. `supabase/schema.sql` contains:

* the tables the code uses (reconstructed from the code — compare with yours first),
* RLS policies: visitors can **insert** enquiries/applications and **read** published
  content only; admins (JWT `app_metadata.role = "admin"`) can do everything,
* storage buckets: `gallery` and `products` public-read, `resumes` **private**
  (visitors can upload, only admins can download),
* the statement that makes a user an admin.

After applying it, verify from a private browser window that
`GET https://<project>.supabase.co/rest/v1/enquiries?select=*` (with the anon key) returns
an empty list, and that the website forms still save.

Also in the Supabase dashboard: **Authentication → Email → disable "Allow new users to sign up"**.

## 5. Admin panel

`pgs/sun.html` — log in with a Supabase user that has the admin role. Sections:
Enquiries (filter, status, Excel export), Gallery, Utility Products, Product Enquiries,
Careers & Placement, Open Roles, Pages. The login lives in memory only: reloading the page
logs you out. Hiding the URL is **not** security — RLS is (see §4).

## 6. Editing pages

The navigation, footer and `<head>` tags are identical on every page and are generated by
`tools/build.py` from the sources in `tools/pages/`:

```bash
python3 tools/build.py    # rewrites index.html and pgs/*.html
```

Edit page content in `tools/pages/<page>.html` and re-run the script. To change the menu or
footer, edit the `NAV` / `FOOTER` templates at the top of `tools/build.py`. If you prefer to
edit the generated HTML directly, that also works — just stop using the build script so
your edits are not overwritten.

**Admin "Pages: content & images"** stores text/image overrides in the `page_content`
table, but `src/sg-content.js` is switched off (`ENABLED = false`; it was already disabled
in the uploaded project). It matches elements by position (e.g. "the 12th paragraph"), so
any change to a page's HTML moves edits to the wrong element. Before enabling it, re-check
every saved edit in Admin → Pages.

## 7. Lead forms

Any form with the `data-sg-enquiry` attribute is validated (name, 10-digit Indian mobile,
optional email, honeypot field `website`) and saved to `enquiries`. A success message is
shown only when Supabase answers with HTTP 2xx; otherwise the visitor sees an error with
the phone number. Add `data-sg-type="…"` to force the enquiry type shown in the admin.

Marketing pop-ups (home page, `src/popup.js`): first after 15 s, then 60 s after each
close, each shown once per visit, and none for 7 days after the visitor sends any form.

## 8. Deployment checklist

1. Copy the `images/` folder into the project root (`IMAGES_REQUIRED.txt` lists every file).
2. Apply/verify `supabase/schema.sql` policies and the admin role (§4).
3. Upload everything except `tools/`, `supabase/`, `.vscode/`, `*.md`, `.env.example`
   (these are harmless if uploaded, `robots.txt` asks crawlers to skip them).
4. Submit `sitemap.xml` in Google Search Console.
5. Go through the "Remaining manual items" in `BUG_REPORT.md`.
